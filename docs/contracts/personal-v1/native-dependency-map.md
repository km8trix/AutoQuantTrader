Supports the single architecture/plan and [account/runtime contract](account-runtime.md). **No item was deleted, disabled, rewritten, built, installed or activated by this inventory.** Superseded describes the personal-v1 target prerequisite, not completion or abandonment of historical work.

## Inventory coverage and how to use it

[File inventory](native-dependency-files.tsv) assigns a disposition, owner and replacement gate to every identified file. [Generator](../../reviews/2026-09-08-wave0/native-map-generator.py.txt) reads tracked UTF-8 source without importing project code, records SHA-256 and line/token references, extracts Python import edges with AST, and computes the reverse consumer closure. The full `native-dependency-inventory.json` is temporary evidence; it contains direct callers/dependencies and line-level lexical references. The generator recreates that full JSON and the original five-column file index; checked-in tables additionally retain SHA-256 and its extracted import-edge records. The checked-in file table preserves the 645 source hashes/dispositions at the initial consolidated document state; the [3,111 direct import edges](native-import-edges.tsv) preserve exact caller/callee paths and line numbers. These tables are the compact review index, not permission to remove a directory. They intentionally predate the new Wave 0 supporting docs; final document hashes are in the baseline artifact manifest.

The scan considered **1,010 tracked files**, all readable UTF-8, excluding `.env`-named files; there were **zero AST parse errors**. There were **351 seeds** selected by native/trusted-time/build/signing-support lexical references, native paths or the shared clock port; their **645-file reverse import closure** is deliberately broad. Of those, 155 receive conditional personal-v1 prerequisite retirement review, 267 are test review, 166 retain-consumer review, 43 supporting/historical documents, 5 shared build/config cutover, 4 migration/schema-history files, 3 pure time modules, and 2 shared persistence files. The closure does not say all 645 files depend on a native runtime effect: ordinary clocks and shared schema imports expand it substantially.

The method covers native C/header sources, Monocypher vendoring, Python imports, dynamic-import/resource references expressed as text, packaging, CI, Make/Compose/systemd, migrations and docs. It does not execute dynamic import branches, inspect private runtime stores/credentials, trace installed artifacts or prove untracked external deployments absent. Root owns exact worktree/untracked/unfinished-integration evidence. Runtime qualification and post-cutover import/effect tests close those limits in W1/W5. The map applies to the reviewed checkout, never to wholesale merging or deleting old worktrees.

## Replacement gates

| Gate | Evidence required before changing the active prerequisite |
|---|---|
| G-TIME | Standard time-health producer supports aware UTC, monotonic elapsed deadlines, source uncertainty, drift/staleness, regression, suspend/wake, epoch changes, equality boundaries and 60 s healthy recovery. Missing health blocks new effects; health alone cannot re-arm |
| G-PROCESS | Ordinary local start/stop and exclusive coordinator ownership. Restart halted; duplicate-start denied; confirmed prior-process termination before takeover; in-flight send claim survives crash; stop works with unavailable clock/data/broker and reports remaining exposure |
| G-FIN | Existing financial/temporal, risk, submission, reservation, ownership, control and accounting invariants still pass; explicit missing-producer rejection, late fill/UNKNOWN hold preservation, account transaction races and policy cutover verified |
| G-DB | Historical tables/revisions and evidence remain readable; full old-to-new migration chain remains valid; no destructive downgrade/drop or release of historical holds. New profile composition need not require old enrollment rows, while those rows remain preserved |
| G-BUILD | Ordinary locked Python package installs/imports on supported personal runtime without native launch authority. API/worker/trader, CLI, standard time producer and tests run through ordinary entry points; secret/process isolation proven; optional legacy native qualification remains explicitly separate |
| G-TEST | Behavior and package boundaries remain tested independently of exact source bytes/doc wording. Replace only mapped native-specific pin/seal/default-launch requirements; retain meaningful forbidden imports/effect isolation and single-use invocation guards |
| G-DOC | One canonical plan/architecture links accepted replacement evidence and preserves historical ADR/runbook scope. No stale target implies native enrollment, old cloud/paper profile or old approval is required/valid for personal-v1 |

W1 runtime lane implements G-TIME/G-PROCESS and proposes package/config separation; the orchestrator owns actual shared `pyproject.toml`, lockfile, Make, CI, architecture-checker/config, schema/migrations and composition edits. W2 risk/engine and W3 research migrate consumers using the frozen contract. W4 account owns durable reconciliation/lease/control consumers. W5 operations proves integrated failure/restore/stop behavior before any remaining old component leaves a runtime prerequisite. A wave owner cannot delete historical resources or bypass a failing old guard as an implementation shortcut.

## Baseline findings that the migration must respect

The root's exact baseline record is authoritative for counts and commands. Its architecture run reported six documentation-literal failures: two invocation-claim requirements and four native opaque launch-lock/lifecycle/activation-blocker claims. No source boundary failure was reported. Do not reinsert a superseded architecture or change checks in Wave 0 just to call this green. W1 must retain the useful durable single-use strategy-invocation and uncertain-in-flight semantics while replacing native lifecycle assumptions and checker wording dependence through reviewed tests.

Native prerequisites are not proven dispensable by passing ordinary financial unit tests. Conversely, a native seal/environment/doc-literal failure does not prove a ledger failure. Keep these outcomes distinct. W0 freezes the map; later removal requires the mapped behavior evidence, including an isolated old-data migration/restore and a standard stop demonstration with unhealthy dependencies.

## Cutover review checklist for the single orchestrator

1. Select exact map rows and their ordinary-profile consumers. Allocate shared schema/composition/CI edits to one owner; do not allow two lanes to update the same pins or migration head.
2. Establish replacement time/process interfaces and tests first. Freeze strict boundary semantics and compatibility for old recorded health/policy data.
3. Rewire standard API/worker/coordinator and package/test entry points without granting effects. Verify imports and ordinary local operations do not resolve native launcher/anchor/enrollment authority; retain safety controls by behavior.
4. Preserve all old rows, evidence and unfinished worktrees. Classify optional legacy entry points explicitly and leave native deployment/resource lifecycle untouched unless separately authorized later.
5. Run G-TIME/G-PROCESS/G-BUILD/G-TEST with exact revisions, and relevant G-FIN/G-DB. Record actual failures/environment gaps; no blanket native-test deletion, fabricated health producer or success-by-stub.
6. In W4/W5, prove account pause/send races, single ownership, UNKNOWN capacity, stop with unhealthy dependencies, restart/restore halted and owner re-arm using the integrated daily runtime. Update the one plan's gate evidence.
