## Accounting and causal admission

The existing immutable Decimal journal, order/correction lineage, FIFO and corporate-action reducers remain the source of economics. An unvalued projection preserves valid fills, units, basis, cash and fees when marks are missing. Authoritative NAV/market value are null with reasons; last-known estimates remain separate. B's cash formula uses settlement cash plus corporate-action-only cash deltas, never the sum of two complete ledgers. Open buy holds cover only unfilled quantities/remaining fee budget; actual filled payables replace covered holds rather than double-reserving them. Pending sales never finance buys.

The engine installs and activates approved modeled requests after the creating decision. It admits all available open-only marks at a frontier before evaluating existing orders against those observations. Decision risk and execution-observation risk are distinct checks; the latter uses current model prices, capacity and existing-commitment overlap. A new order cannot consume any observation in its creating/activation frontier, and an observation's economic time must be strictly after activation. A gap beyond safe cash capacity halts/rejects new simulated execution while preserving the commitment until an explicit modeled disposition. An already admitted authoritative execution fact is still recorded even when it breaches a reserve; resulting negative capacity/uncertainty halts new exposure.

Default schedules come from RunSpec's pinned exchange calendar: decision 20:00 ET, missing-input cutoff strictly before next-session 09:00, next-open proxy distinctly modeled, DAY close from the actual supplied session (including half-days). A owns these schedule events and all B-returned due events. Explicit timer/oracle schedule inputs have separate identities and do not reopen a consumed daily decision. Missing required feature sessions reset contiguous history; weekends/holidays absent from the supplied grid do not. Warmup supplies causally available history only; scored account/strategy state starts fresh.

The model may authoritatively expire a still-supported DAY remainder at its intended close using `ModelDisposition(day_expired)` and a pinned model evidence ID. UNKNOWN/pending-cancel does not expire merely with time; it retains holds until separate explicit synthetic terminal evidence or a supported broker fact. Corrections never implicitly reopen an order. Final commitment quantity is distinct from the old reducer's original-minus-filled property after cancellation.

Settlement uses a separately supplied immutable business-date calendar, not a guessed weekday/exchange grid. Frozen cycles are T+3 before 2017-09-05, T+2 through 2024-05-27, T+1 thereafter, with modeled 09:30 ET release. Corrections/busts use explicit oracle instructions when supplied, otherwise the pinned receipt-local-trade-date standard cycle, never retroactive availability. Coverage exhaustion rejects scheduling. Cash release requires the engine to apply the returned confirmation event. Price slippage is adverse bps; buys round upward and sells downward to the named 1e-10 price quantum. Fees are per filled share, once; there is no hidden fixed fee or claimed liquidity from daily volume.

## Results, returns and identity

`EngineResult.executions` and `fifo_matches` are the final unique effective heads; complete earlier fact/correction history remains in final_state and immutable trace. Do not concatenate replacement projection rows as new economics. B owns split-aware FIFO fee lineage; match fee amounts are derived once from exact rational attribution, and closing-order groups complete only with authoritative/model terminal evidence. Portfolio fees are expensed once even on open positions; trade attribution never reposts fees.

ValuationRow wraps AccountSnapshot to avoid duplicated amounts. Distinct rows have increasing engine reduction sequences; combine daily-close/terminal roles when they refer to one snapshot. At each external flow, A issues adjacent pre/post valuations with identical causal marks, applies the fact once, and binds both rows to its journal evidence. Initial funding's zero-NAV pre-flow row is retained outside the scored interval; the funded post-flow snapshot establishes the positive baseline. Initial capital is not a later contribution.

C's one wealth reducer supplies both risk and reporting. It uses 64-significant-digit, half-even derived arithmetic; signed cash flows remain exact persisted money, while analytical benchmark NAV may have derived fractional precision. Missing/nonpositive authoritative values invalidate the affected full return path; do not bridge a gap. E4/E5 exact event-timed TWR is 21%. Annualized metrics require 252 complete scored session returns plus a baseline; zero variance makes Sharpe and Sortino undefined. Sortino uses all-sample downside second moment and this explicit conservative zero-variance rule. Turnover includes all effective executed notionals over mean valid daily NAV; exposure is a mean daily ratio.

The analytical SPY comparator uses a single pinned total-return unit-price representation with the same ordered flow boundaries, zero fees and explicitly permitted fractional analytical units. Root provides causal boundary prices; missing boundary prices make the comparator undefined. Never add raw dividends again to an adjusted series. Apply post-flow analytical NAV as pre-flow NAV plus flow under the shared context, avoiding a second rounding route. Idle cash uses the same flows and assumed zero interest.

Run identity binds actual dataset/events, calendars, source/build/dependency/numeric/model/configuration/scoring pins and limitations. Generation time/attempt affect only artifact identity. Event causal-content hashes omit run-wide/raw-file aggregate pins so a future-row change can change run identity while leaving the earlier causal decision projection unchanged. Full provenance remains in the enclosing inputs/result. Public fixtures stay synthetic; current-vintage data never acquire invented historical receipt/publication facts. Unsupported carry, stochastic models, corporate actions or resource limits reject explicitly rather than silently weakening the run.

## Consumer seam resolution

AccountingState retains the original engine ReductionPoint of every admitted broker fact and each accepted execution observation. Source observation IDs and hashes are deduplicated independently of command IDs, including observations that caused no fill. InstallCommitment binds the DailyRiskPolicy hash and the source approved AccountSnapshot carried by AccountingContext. B validates that binding/account/nonfuture point and current remaining capacity; A validates batch freshness and rolls back the entire batch if any installation rejects. Separate sequential installations cannot hide combined capacity use.

Explicit settlement instructions may wait for their exact execution fact, with no economic effect until matched. An instruction already provided for that fact takes precedence over the default model; a conflicting instruction arriving after modeled settlement was fixed is rejected. Modeled withdrawal requests exceeding available cash after commitments reject before posting. Admitted executions remain authoritative even when capacity is negative.

BenchmarkPrice is a separate causal engine input. Its unit price never becomes an account execution/valuation mark. A binds the latest accepted benchmark input to each valuation only when its economic boundary matches the valuation; a missing boundary stays undefined. Equal-frontier benchmark inputs are ingested before valuations and never after callbacks. Synthetic oracle flow marks explicitly supply both account marks and comparator prices. Real-data adjusted closing prices do not establish a same-day opening adjusted price.

The default funded baseline is the last warmup session's close with its available knowledge, before the first scored session. A zero-warmup run uses the first scored session opening boundary; any missing comparator boundary is explicit. Warmup receives history but no strategy calls/orders. Product EngineInputs start with an empty pinned AccountingState; the engine journals RunSpec.initial_cash exactly once. Explicit synthetic-oracle inputs may instead provide a previously funded state with initial_cash zero; its complete financial facts, original points and identity must be reconstructable at the baseline. Continuous account carry is unsupported.

The engine API is run_causal_engine(inputs, *, accounting, strategy, stop_requested=None). Ports are injected; only the application engine owns scheduling. An extra supplied calendar session may define the last decision's execution horizon without extending the scored interval or inventing a future fill. Root supplies strategy, immutable input builders and a process-bounded CLI. Workers do not create independent calendars, data loaders or report truth.
