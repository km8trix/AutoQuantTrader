The factory already decodes its three retained configuration objects before acquisition (`continuous_simulation_factory.py:249–303`); repeating them is not a useful work subset. `_validate` freshly captures and compares the complete schema snapshot, including lease/head/release dependencies (`continuous_integrity.py:1954`). `_read_snapshot` establishes daily ownership only after an actual fence revalidation (`daily_runtime_risk.py:1495`). These checks cannot be replaced by provisional decoding.

The closest acquisition precedent is `acquire_if_inactive_generation` (`account_coordinator.py:959`): original state lock, exact generation/inactive check on the locked SQL head, trusted-clock check, one revision-1 insert, exact after-head readback, and return after transaction commit. It does **not** return ownership of its complete predecessor. Existing `acquire` also permits missing-head bootstrap or returning an existing same-owner lease; neither qualifies for the proposed narrow study. Exact before/after equality cannot itself prove who performed the transition.

Before any prototype, require a named finite pure decoding/canonical subset, exact input bytes/row projections and its consumer. Specify which repeated computation it would replace while retaining all original validation predicates. If the proposed consumer needs identity-check substitution, another general cache, a snapshot exemption or rebinding existing receipts, reject this study branch. The architecture review must settle ownership of the locked predecessor and the post-commit/pre-return failure window before a model can represent successful handoff.

## Small model surface and independent oracles

Use a temporary pure transition model, not fabricated registrations in production owners. Represent only: preparation owner/operation/thread identity, original provisional input inventory, exact inactive predecessor, actual acquisition transition, consumption phase, and cleanup responsibility. Model records never satisfy production source/fence/receipt APIs. A passing symbolic model is not an authentic coordinator witness.

Keep three independent oracles: (1) literal original decoding/canonical result and exception/read order for the selected subset; (2) exact immutable pre/post row inventories with only the two explicitly allowed acquisition changes; (3) a short, independently written phase/effect trace. Do not derive expected output by calling the candidate's own predicate or compare only a final digest. An eventual source-owned experiment must observe the original coordinator's transaction and real receipts; it cannot manufacture a witness from equivalent external facts.

Minimum phase trace to specify, without prescribing a new production API: provisional preparation → acquisition pending → commit established and cleanup owned → fresh comparison → one original handoff/use → terminal checks → retirement. Rollback, Stop, mutation or ownership mismatch cannot become success by restoring fields or retrying. Model effect counters distinguish pure work, SQL reads, coordinator write/commit, original fresh checks, output exposure and cleanup.

## Resource rejection gates

Account by phase and peak overlap, before constructing large snapshots. Tabulate at least provisional raw bytes, decoded objects, native/behavior bindings, owner/witness registry state, traversal scratch/pending lists, fresh coherent rows, existing attempt proof, original handoff, fresh handoff and cleanup-retained state. Count actual overlapping references/containers/edges; an alias may share its object but repeated edges still cost. Independently model deep, wide, shared and cyclic shapes with exact-bound and bound-plus-one cases. Checks must reject before an extra read/allocation whose size exceeds the remaining allowance; custom iteration/getter counters prove no oversized fallback traversal occurs.

Existing limit families are separate and cannot be added together as a new discretionary pool:

- Factory structure profile `original-and-fresh-structure/2`: original ≤16,384 containers; fresh ≤16,384; combined ≤32,768; **one combined 131,072-binding allowance** (`continuous_integrity.py:407–410, 684–701`). Existing attempt proof shares its original-phase cap and retires before handoff construction. A third overlapping preparation is not automatically entitled to another allowance. The study must map its state onto the existing phases or reject.
- Coherent integrity SQL capture: 65,536 rows and 128 MiB across financial and dependency tables (`database.py:177–178`). Dependencies remain charged; no new lease-table exemption.
- Daily capture: 4,096 rows/table, 16,384 total rows, 32 MiB payload and 2 MiB metadata (`daily_runtime_risk.py:143–144, 251–278`). Preserve the actual per-field transfer limits and shared producer footprint too.
- Original detached artifact closure: 32 MiB plus bounded reference count (`continuous_integrity._OriginalObjects`). Codec's separate 64 MiB record/depth-64 limits do not enlarge that closure bound.
- Preserve the retained fixture's 60-second lease, 120-second wall timer and 150-second parent bound where applicable. Preserve the separate worker's configured wall/CPU/memory bounds (default 30 seconds/30 seconds/512 MiB); parent wall time is not a CPU allowance.

Require a joint lower-bound inventory first, including all required ownership/dependency metadata. ## Escalation sequence and acceptance limits

1. Source-bound phase/owner/effect model and resource table; independent review. No source patches or heavy fixture.
2. Small temporary scalar mechanics tests against independent row/transition/original-code oracles. Synthetic ownership must be labeled as such. Zero effects beyond controlled offline callbacks.
3. Only if all previous gates survive: separately review one exact original synthetic fixture command, source/script hashes, input/output caps and cleanup. Prefer the small `test_sql_account_coordinator.py` conditional-acquisition fixtures for genuine predecessor/commit evidence before the retained multi-minute graph. SQLite success is not PostgreSQL concurrency acceptance. Do not bypass signing/clock/receipt ownership or construct production registry entries.
4. Only with a coherent original-owned handoff and a resource fit: bounded complete-cost experiment. Measure preparation-through-cleanup, lease-held work, process/CPU/memory and failure paths; include extra reads/comparison/construction/retirement cost. A shorter execute region alone does not show savings or predict Linux acceptance. Keep unchanged tests/limits; no parallel heavy tests.
5. Return feasible-with-explicit-limitations or rejected. Production adoption, owner API changes and acceptance require a further decision and the original retained, worker, financial, concurrency and exact-source CI gates.
